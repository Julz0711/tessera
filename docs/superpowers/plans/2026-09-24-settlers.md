# Settlers Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Build the playable browser game described in `prompt.md` / the design spec: guest-first private rooms, 3D board, Classic + Cities & Knights, bots, chat, spectators, reconnect, optional Google/Discord profiles with history.

**Architecture:** One Node process (`server.ts`) serves Next.js and Socket.IO. A pure, seeded rules engine (`src/engine`) is the single source of truth; the server applies client intents through it and pushes redacted per-seat views. Persistence/auth (Prisma + Auth.js) are optional layers activated by env vars.

**Tech Stack:** Next.js 16, React 19, TypeScript 5.9, @react-three/fiber 9 + drei 10 + three, Socket.IO 4.8, Prisma 7 (+ @prisma/adapter-pg), Auth.js v5 (next-auth@beta), Tailwind 4, Zustand 5, Vitest 5, tsx.

Spec: `docs/superpowers/specs/2026-09-24-settlers-design.md`.

**Deviation from the writing-plans template (deliberate):** the plan lists contracts, files, tests and verification commands but does not duplicate full source code — the code *is* the deliverable and is authored directly (≈17k lines). Engine tasks are still test-first.

## Core contracts (all later tasks depend on these names)

```ts
// src/engine/types.ts
type Resource = 'brick'|'lumber'|'wool'|'grain'|'ore'; type Commodity = 'paper'|'cloth'|'coin';
type Card = Resource|Commodity; type Hand = Record<Card, number>;
type Terrain = 'forest'|'hills'|'pasture'|'fields'|'mountains'|'desert';
type Track = 'trade'|'politics'|'science';
type Mode = 'classic'|'ck';
interface GameState { mode; settings; board; players: PlayerState[]; bank: Hand; devDeck; progressDecks;
  buildings: (Building|null)[]; roads: (number|null)[]; knights: (Knight|null)[];
  phase: 'setup'|'play'|'ended'; turn: TurnState; pending: Prompt[]; steps: Step[];
  trades: TradeOffer[]; longestRoad: number|null; largestArmy: number|null; barbarian; metropolis;
  log: GameEvent[]; winner: number|null; rng: number; seq: number; }
// src/engine/index.ts
createGame(opts): GameState
applyAction(state, seat, action): {ok:true,state,events} | {ok:false,error}
viewFor(state, viewer: number|null): PlayerView
actorsFor(state): number[]            // seats that currently owe a decision
legalRoads / legalSettlements / legalCities / … (state, seat)
// src/bots/index.ts
botAction(view: PlayerView, seat: number, ctx?): Action|null
```

Board topology is derived (memoised) from hex coordinates: vertex key = scaled integer corner position `(2q+r+dx, 3r+dy)`, `dx,dy ∈ {(0,-2),(1,-1),(1,1),(0,2),(-1,1),(-1,-1)}`; standard board = 19 hexes / 54 vertices / 72 edges / 30 coast edges.

Flow control: `pending` holds simultaneous prompts (discard, robber, freeRoads, loseCity, relocateKnight, …); `steps` holds continuation steps (produce, barbarian, progressDraw, …) run by `advance()` whenever `pending` is empty.

## Status (2026-09-25)

All phases implemented and verified (`npx tsc --noEmit`, `npx vitest run` — engine, 150 classic + 120 C&K bot self-play games, server integration incl. full games through Socket.IO, DB persistence/migration tests; `next build`; browser runs in 2D/3D, desktop and phone sizes).

Deviations from the original plan:
- **Auth.js** runs through `@auth/core` inside the custom server (`src/server/auth.ts`) instead of a Next.js route: keeps all DB code out of Next bundles (Turbopack could not create the junctions it needs for server-external packages on this machine's drive) and gives one module graph for sessions.
- **Knight customization** (round-1 feedback): one basic knight in the player's color with an optional uploaded face (`/api/face`), instead of helmet/armor/emblem options.
- **Terrain** (round-1 feedback): layered tiles; contained mountains/clay pits; wheat plots with barns; denser forests.
