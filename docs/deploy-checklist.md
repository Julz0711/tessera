# Deploy checklist

What to check before and after a bigger deploy to Render (free web service `tessera`) with the Neon
database. Small fixes only need the first section.

## 1. Before every push

- [ ] Production builds require real `NEXT_PUBLIC_LEGAL_OPERATOR`, `_ADDRESS`, and `_EMAIL`.
      Configure them before deploying; development still supports placeholders.
- [ ] `npm run typecheck` and `npm test` pass.
- [ ] `npm run build` works locally. Render runs the same build, and a failed build means the old
      version keeps running, so it isn't an outage, but the new version won't go out.
- [ ] `git checkout -- tsconfig.json` if a local dev server rewrote it.
- [ ] A new entry at the top of `src/config/patchNotes.ts` if players will notice the change.

## 2. Database changes (`prisma/schema.prisma`)

The build runs `prisma db push`, which **refuses changes that would delete data** and then fails the
build. Examples: dropping or renaming a column or table, or making an optional column required.

- [ ] Adding a new table or an optional column: safe, nothing to do.
- [ ] Renaming or removing something: do it in two deploys. First add the new field and copy the
      data over, then remove the old field once nothing uses it.
- [ ] Before anything risky, create a branch or backup in the Neon console. On the free plan the
      restore window is short, so do it right before the deploy.
- [ ] The free Neon plan has 0.5 GB. Game events and snapshots grow with every game, so glance at
      the size in the Neon console now and then.

## 3. During the deploy

- [ ] Deploy when nobody is mid-game. Games in progress are restored from the database after the
      restart, but chat and open lobbies are lost, and everyone reconnects.
- [ ] The first visit after a deploy or after 15 idle minutes takes about a minute (the free server
      wakes up). That's normal, not a crash.

## 4. After the deploy

- [ ] Open the live site: create a game with a bot and play a few turns.
- [ ] Sign in with Google and with Discord (if they're configured).
- [ ] Check `/privacy` and `/terms` show your real name, address and email, not `[placeholders]`.

## 5. Only when these change

**New environment variables.** Add them on the Render service before pushing. Variables starting
with `NEXT_PUBLIC_` are baked in at build time, so change them first and redeploy afterwards.

| Variable | Notes |
| --- | --- |
| `DATABASE_URL` | Neon connection string. Never commit it. |
| `DIRECT_DATABASE_URL` | Unpooled connection to the same database when `DATABASE_URL` is pooled. Required for privacy maintenance locks. |
| `AUTH_SECRET` | Generated by Render. Changing it signs everyone out and turns all guests into new guests. |
| `AUTH_GOOGLE_ID` / `_SECRET`, `AUTH_DISCORD_ID` / `_SECRET` | Optional sign-in. |
| `TRUST_PROXY=1` | Set by `render.yaml`; keeps rate limiting per player instead of per Render proxy. |
| `APP_URL`, `ALLOWED_ORIGINS` | Only if the game is also opened from another domain. |
| `NEXT_PUBLIC_LEGAL_OPERATOR`, `_ADDRESS`, `_EMAIL`, `_COUNTRY` | Shown in the privacy policy and terms. |
| `NEXT_PUBLIC_APP_NAME` | Leave unset (defaults to Tessera). |

**A new address (own domain or new service).** Everything tied to the old address resets: players
sign in again, guests start fresh, settings are lost. Also:

- [ ] Add `https://<address>/api/auth/callback/google` in the Google Cloud console and
      `https://<address>/api/auth/callback/discord` in the Discord developer portal.
- [ ] Don't rename the service in `render.yaml`. Render then creates a second service instead of
      renaming it, and both share the 750 free hours a month. Use a custom domain instead.
- [ ] Send the new link to your players.

**What data the game stores.** If you add anything new that is stored or shown about players (new
profile fields, analytics, error tracking, email, uploads, a new outside service):

- [ ] Update `src/app/privacy/page.tsx` (what's stored, who can see it, which providers).
- [ ] Bump `LEGAL_UPDATED` in `src/config/legal.ts`.
- [ ] Include new personal-data fields in deletion and portrait-reference checks. Follow
      [privacy operations](privacy-operations.md) for verified deletion requests.
- [ ] Analytics or anything non-essential that sets cookies or uses local storage needs a consent
      banner in the EU. Avoid it, or ask first.

**Names, art and money.**

- [ ] No "Catan", "Settlers", "Colonist", "Cities & Knights" or "Seafarers" anywhere players see
      (UI, patch notes, page titles, README, store or social posts). Code comments are fine.
- [ ] Our own art only: no copied card art, number tokens or box design.
- [ ] Adding ads, donations or paid features makes the game commercial. Catan's IP policy counts
      ad-supported sites as commercial use, and a commercial site in Germany needs an Impressum.
      Get legal advice first.

## Free-tier limits to keep in mind

- Render: 750 free hours a month for all free services together. A sleeping service uses none. If
  they run out, every free service is suspended until the 1st of the next month. Delete services
  you no longer use.
- Neon: 0.5 GB storage, doesn't expire.
